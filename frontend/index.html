Exemples rapides à tester :

Flux appliqué :

  1. Front-end : Envoie la question utilisateur à l'API IA.
  2. Module IA : Extrait les concepts de l'ontologie et formule la requête SPARQL.
  3. Fuseki API : Reçoit la requête SPARQL et sollicite le moteur RDFLib.
  4. RDFLib + OWL : Exécute la requête sur le graphe OWL de Personne.

Explication de l'Architecture Implémentée

Conforme à la diapositive Projet
💻

1. Front-end (Interfaces Utilisateurs)

Interface web moderne développée en HTML5/CSS3/Vanilla JS. Elle permet à l'utilisateur de poser ses questions en français, d'interroger la base SPARQL et de naviguer dans les fiches de la classe Personne.

🤖

2. Module IA (API NLP ➔ SPARQL)

Composant d'intelligence artificielle qui traduit la question de l'utilisateur en requête formelle SPARQL conforme aux classes (Medecin, Patient, Stagiaire) et propriétés (soigne, connait, age) de l'ontologie.

🗄️

3. Fuseki (API SPARQL JSON)

Endpoint HTTP SPARQL normalisé (identique à Apache Jena Fuseki). Il reçoit les requêtes SPARQL issues de l'IA ou du Front-end et renvoie les réponses sous format JSON standardisé (head/vars et results/bindings).

🐍

4. Back-end (Python + RDFLib)

Serveur Python (Flask + RDFLib) assurant la gestion du graphe RDF/OWL en mémoire, l'exécution des requêtes SPARQL et le calcul des inférences de symétrie et de transitivité.

🌐

5. Protégé & OWL (Classe Personne)

Le fichier ontologie_personne.owl conçu sous Protégé / Owlready2, contenant les classes, sous-classes, disjonctions, propriétés objet et de données propres au module Personne.
